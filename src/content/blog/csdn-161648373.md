```java
public class Singleton {    private static Singleton instance; // ❌ 缺少 volatile     public static Singleton getInstance() {        if (instance == null) {                 // 第一次检查（无锁，提高性能）            synchronized (Singleton.class) {                if (instance == null) {         // 第二次检查（持锁，保证唯一）                    instance = new Singleton(); // ⚠️ 隐患就在这一行                }            }        }        return instance;    }}
```


双重检查（Double-Checked Locking）的设计初衷是好的：第一次检查避免每次都加锁，第二次检查保证只创建一个实例。逻辑上无懈可击——**问题出在new Singleton() 不是原子操作。**


#### 原因:new一个对象其实是三步


`instance = new Singleton()` 编译成字节码后，核心是这几条指令：


```java
new           // ① 分配内存空间invokespecial // ② 调用构造方法，初始化对象astore /putstatic // ③ 把对象的引用赋值给 instance 变量
```


可以抽象成 3 步：


1. **分配内存**（此时 instance 仍指向 null）
2. **初始化对象**（执行构造方法，填充字段）
3. **将 instance 指向这块内存**（此后 instance != null）


为了优化性能，**JVM(JIT) 和 CPU 允许在不影响单线程结果的前提下对指令重排序**。第 ② 步和第 ③ 步没有数据依赖，于是可能被重排成 **1 → 3 → 2**：


1. 分配内存
2. **将 instance 指向内存（此时 instance != null，但对象还没初始化！这个在多线程场景下就会出现问题）**
3. 初始化对象


| 时刻 | 线程 A | 线程 B |
| --- | --- | --- |
| t1 | 执行 1→3：instance 已非 null，但对象未初始化 | — |
| t2 | （被挂起，还没执行第 2 步初始化） | 第一次检查 instance == null？为 false |
| t3 | — | 直接 return instance ⚠️ 拿到半成品对象 |
| t4 | — | 访问对象字段 → 可能 NPE 或读到默认值 |


线程 B 通过第一次检查（无锁）看到了一个「引用非 null 但内部还没构造完」的对象。这就是**经典的「对象逸出 / 半初始化」问题，这里就会导致我们的单例模式失效NPE问题可能发生。**


#### **解决方案1：**给字段加volatile


#### 


`volatile` 在这里干了**两件事**（对应你 Q8 答对的可见性 + 漏掉的禁止重排序）：


- **可见性**：一个线程写入后，其他线程立即可见（强制刷主内存、使其他 CPU 缓存失效）。
- **禁止指令重排序**：通过**内存屏障（Memory Barrier）**保证 ②③ 不会被重排，即「初始化完成」一定 happens-before「引用赋值」。


底层上，写 volatile 变量后会插入 **StoreStore + StoreLoad 屏障**，读之前插入 **LoadLoad + LoadStore 屏障**，从而禁止屏障两侧的指令跨越重排。**这样就可以保证是严格的1->2->3的顺序而不是会出现重排序的new初始化情况**


#### 解决方案2:使用其他更优雅的单例模式写法


##### 方案 A：静态内部
 类 **
 （推荐，懒加载）


```java
public class Singleton {    private Singleton() {}    private static class Holder {        static final Singleton INSTANCE = new Singleton();    }    public static Singleton getInstance() {        return Holder.INSTANCE;    }}
```


原理：**类初始化由 JVM 用锁保证只执行一次**（类加载的 `<clinit>` 阶段有同步），且 Holder 类只有在第一次调用 `getInstance()` 时才被加载 → 实现懒加载 + 线程安全。


**方案 B：枚举（防反射/反序列化攻击）**


```java
public enum Singleton {    INSTANCE;    public void doSomething() { /* ... */ }}
```
