## Redis采用Hash slot进行分片


Redis则是利用散列插槽（hash slot）的方式实现数据分片


- Redis Cluster 将整个逻辑存储空间固定划分为 16384 个哈希槽（编号 0 ~ 16383）
- 每一个 Master（主）节点都会被分配一部分槽位。例如，在 3 主节点的集群中，每个节点大约负责管理 5461 个槽位(这个是自己配置的)![图片](/Blog/images/csdn/158462452/01.png)
- Redis默认是基于CRC16算法对key做hash运算，得到的结果与16384取余，就计算出了这个key的slot值。然后到slot所在的Redis节点执行读写操作
- 当客户端向集群写入或读取一个 Key 时，Redis 会通过以下公式计算该 Key 属于哪个槽：  HASH_SLOT = CRC16(key) & 16383得出槽位编号后，数据就会被精确存储到负责该槽位的物理节点上


## 分布式 **
 分流类软件采用一致性哈希


这是一种负载均衡的方式，实现起来比较负载，目的是解决动态扩展导致哈希找不到桶的现象


![图片](/Blog/images/csdn/158462452/02.png)


我们增加了一个节点，节点的数量从 3 变化为 4，意味取模哈希函数中基数的变化，这样会导致大部分映射关系改变，然后就会导致原来可以查找到的数据现在找不到了


**一致性哈希是指将「存储节点」和「数据」都映射到一个首尾相连的哈希环上**


一致哈希算法是对2^32进行取模运算，是一个固定的值(因为是一个固定值，因此就不会出现上面的问题)，**就是我们不再使用动态的节点数作为哈希值的处理对象了**


但是一致性哈希算法并不保证节点能够在哈希环上分布均匀，这样就会带来一个问题，会有大量的请求集中在一个节点上


![图片](/Blog/images/csdn/158462452/03.png)


因此我们就需要引入虚拟节点来进行负载均衡(而且还需要根据对应实体机器的性能来)


**不再将真实节点映射到哈希环上，而是将虚拟节点映射到哈希环上，并将虚拟节点映射到实际节点，所以这里有「两层」映射关系**

## 有状态和无状态的区别


无状态 (Stateless)：**节点本地不存任何业务数据**。它只负责“计算”或“处理”→比如
 微服务 **
 的服务提供者 Provider，使用一致性哈希仅仅是为了分散流量(分流)，扩容/缩容的成本低(比如改变一下IP路由表啥的)，比如**跟云原生有关的都是要求这样的**


有状态 (Stateful)：节点本地的
 内存 **
 或磁盘里，物理保存着独一无二的业务数据，必须稳定，不可以有风险，扩容风险高(需要搬运数据)，比如Redis


**为了保证数据安全，Redis放弃了这种自动动态变更哈希的方式，因为动态变更意味着会大量数据搬运，在高并发的情况下会有数据风险**


但是这不意味着Redis不可以修改和搬运哈希桶里面的数据，Redis官方提供了工具让你手动操作，这样数据就会安全很多


## 对比分析


- **一致性哈希**：是一种 `Key -> Node` 的直接映射。数据和节点被放在同一个 232232 的哈希环上，Key 顺时针寻找碰到的第一个物理节点。
- **哈希槽**：是一种 `Key -> Slot -> Node` 的两级映射。Redis 强行规定了 16384 个槽位。Key 计算出所属的 Slot，而 Slot 分配给哪个 Node，是由集群的元数据表（分片规则）人为指定的。


| 对比维度 | 一致性哈希 (Consistent Hashing) | Redis 哈希槽 (Hash Slots) |
| --- | --- | --- |
| 映射层级 | Key -> 物理节点 (单层直达) | Key -> Slot -> 物理节点 (引入中间层) |
| 寻址空间 | 2322^{32}232﻿ (极其庞大，形成哈希环) | 固定 16384 (极小且固定) |
| 解决数据倾斜 | 强依赖算法，必须引入大量“虚拟节点” | 极其灵活，直接人工指定各机器负责的 Slot 数量 |
| 动态扩缩容（数据迁移） | 极难：数据边界模糊，需计算环上受影响的特定 Key，全盘扫描成本极高 | 极简：以 Slot 为单位“搬箱子”，边界绝对清晰，指哪打哪 |
| 集群元数据同步开销 | 巨大：需在节点间高频同步庞大且复杂的虚拟节点映射表 | 极小：只需在 Gossip 协议中携带 2KB 的 Bitmap (位图) 即可完全表达 |
| 典型适用场景 | 无状态的缓存路由或负载均衡 (如早期的 Memcached、Nginx 负载) | 有状态的分布式数据库底层分片 (如 Redis Cluster) |
