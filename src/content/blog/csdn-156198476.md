ArrayList的底层是数组队列，相当于动态数组。容量能动态增长


ArrayList实现了List<E>, RandomAccess, Cloneable, java.io.Serializable的接口


- `List` : 表明它是一个列表，支持添加、删除、查找等操作，并且可以通过下标进行访问。
- `RandomAccess` ：这是一个标志接口，表明实现这个接口的 `List` 集合是支持 **快速随机访问** 的。在 `ArrayList` 中，我们即可以通过元素的序号快速获取元素对象，这就是快速随机访问。
- `Cloneable` ：表明它具有拷贝能力，可以进行深拷贝或浅拷贝操作。
- `Serializable` : 表明它可以进行序列化操作，也就是可以将对象转换为字节流进行持久化存储或网络传输，非常方便。

ArrayList有三个默认的构造器，我们其实可以发现，基本上也是new操作+Arrays.copyOf就可以实现这些的


个人觉得这里面最关键的部分就是扩容机制，ArrayList的默认扩容机制是1.5倍的方式

可以发现ArraysSupport.newLength(oldCapacity, minCapacity - oldCapacity, oldCapacity >> 1 是扩容的关键，而扩容后大小是oldCapacity + oldCapacity >> 1，也就是我们说的1.5倍进行扩容


**此外，有关ArrayList的使用我们需要注意：**


** 1. 因为grow方法的开销很大，所以有的时候使用有参构造器来进行初始化才是好的选择，否则频繁的grow会拖累性能的(不要new一个无参构造然后for循环里面一直add)**


** 2. ArrayList 的底层是数组，内存是连续的，尾部操作是很快的，但是头部和中间操作是复杂度高的**


** 3. 避开迭代器陷阱：不要在遍历时 remove，会导致抛出ConcurrentModification Exception的异常的(modcount是ArrayList 的“版本号”。每当数组结构发生变化（扩容、删除），这个值就加 1。它是为了实现 Fail-Fast（快速失败)）**


** 4. list.subList(from, to) 返回的不是一个新 List，而是原 List 的一个视图（View）。因此你修改 subList 里的值，原 list 也会变。如果原 list 进行了结构性修改（如 add 或 remove），那么之前生成的 subList 就会直接作废（抛出异常）**


** 5. 没有加锁，不是线程安全的，多线程下应该使用Collections.synchronizedList(new ArrayList<>())**


** 6. ArrayList 中可以存储任何类型的对象，包括 null 值。不过，不建议向ArrayList 中添加 null 值， null 值无意义，会让代码难以维护比如忘记做判空处理就会导致空指针异常**
