Vector**在Java 1.0版本中就已经存在(里面的方法名字特别长)**，底层实现是基于Object数组的，每次增加元素时都会检查当前容量是否足够，如果不够则会自动扩容，同时将原数组中的元素复制到新数组中(这里面的扩容机制和ArrayList不一样)


也实现了List<E>, RandomAccess, Cloneable, java.io.Serializabl接口，这些都很常见就不重复了


```java
    protected Object[] elementData;    protected int elementCount;    protected int capacityIncrement;
```


- 都是 protected 而不是 private，目的是为了方便子类继承和扩展。但是在现代 Java 设计（如 ArrayList）中，通常倾向于使用 private 以增强封装性，而 Vector 保留这种设计主要是为了兼容性


```java
public Vector(int initialCapacity, int capacityIncrement) {        super();        if (initialCapacity < 0)            throw new IllegalArgumentException("Illegal Capacity: "+                                               initialCapacity);        this.elementData = new Object[initialCapacity];        this.capacityIncrement = capacityIncrement;    }    public Vector(int initialCapacity) {        this(initialCapacity, 0);    }    public Vector() {        this(10);    }//默认大小是10    public Vector(Collection<? extends E> c) {        Object[] a = c.toArray();        elementCount = a.length;        if (c.getClass() == ArrayList.class) {//如果是ArrayList的话那么直接转换就可以了，不用执行复制操作            elementData = a;        } else {            elementData = Arrays.copyOf(a, elementCount, Object[].class);//其他的需要进行复制        }    }//也可以使用集合来初始化
```


从构造器里面可以看出来，无参构造默认的初始化大小是10,而且我们还可以传入一个集合来封装到Vector里面，当然也支持有参构造


这里面的capacityIncrement主要是为了扩容的


```java
public synchronized void ensureCapacity(int minCapacity) {        if (minCapacity > 0) {            modCount++;            if (minCapacity > elementData.length)                grow(minCapacity);        }    }    //扩容    private Object[] grow(int minCapacity) {        int oldCapacity = elementData.length;        int newCapacity = ArraysSupport.newLength(oldCapacity,                minCapacity - oldCapacity, /* minimum growth */                capacityIncrement > 0 ? capacityIncrement : oldCapacity//如果开发者手动设置了增长步长（capacityIncrement），就按步长增加，如果没有设置步长，默认会增加 oldCapacity 的长度                //也就是Vector里面的扩容都是默认2倍进行的                                           /* preferred growth */);        return elementData = Arrays.copyOf(elementData, newCapacity);    }//具体扩容调用的函数和ArrayList是一样的    public static int newLength(int oldLength, int minGrowth, int prefGrowth) {        // preconditions not checked because of inlining        // assert oldLength >= 0        // assert minGrowth > 0         int prefLength = oldLength + Math.max(minGrowth, prefGrowth); // might overflow        if (0 < prefLength && prefLength <= SOFT_MAX_ARRAY_LENGTH) {            return prefLength;        } else {            // put code cold in a separate method            return hugeLength(oldLength, minGrowth);        }    }    private static int hugeLength(int oldLength, int minGrowth) {        int minLength = oldLength + minGrowth;        if (minLength < 0) { // overflow            throw new OutOfMemoryError(                "Required array length " + oldLength + " + " + minGrowth + " is too large");        } else if (minLength <= SOFT_MAX_ARRAY_LENGTH) {            return SOFT_MAX_ARRAY_LENGTH;        } else {            return minLength;        }    }
```


他的扩容代码和ArrayList是很像的，但是关键步骤(扩容策略)不一样


ArraysSupport.newLength(oldCapacity, minCapacity - oldCapacity, capacityIncrement > 0 ? capacityIncrement : oldCapacity


如果开发者手动设置了增长步长（capacityIncrement），就按步长增加，如果没有设置步长，默认会增加 oldCapacity 的长度(也就是空间直接翻倍，当然实际上相对于1.5倍，2倍的设计不太合理，可能会导致大量空间浪费->不推荐)


1. 为了保证线程
 安全性 **
 ，Vector采用了synchronized关键字对部分方法进行同步，由于每个操作都要竞争锁，即使是在单线程环境下，Vector 的性能也比 ArrayList 慢很多


2. Vector 基本上已经不再建议在新
 项目 **
 中使用，因为即使 Vector 的每个方法都是同步的，它也不能保证复杂的复合操作安全，而有关集合的东西往往都是复合操作，因此里面的锁显得有点多余了
